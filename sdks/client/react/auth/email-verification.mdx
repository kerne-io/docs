---
title: "Email verification"
description: "Verify a user's email, client-side"
---

`useAuth()` exposes the full verification flow directly - no need to proxy it through your own API routes.

```tsx
import { useAuth } from '@kerne/react';

function VerifyBanner() {
  const { sendVerificationEmail, getVerificationStatus } = useAuth();

  return (
    <button onClick={() => sendVerificationEmail('code')}>
      Send verification email
    </button>
  );
}
```

## Verify with a code

```tsx
const { verifyEmailWithCode } = useAuth();

const { success, needsTokenRefresh } = await verifyEmailWithCode('483920');
if (needsTokenRefresh) {
  // the access token's email_verified claim is stale - refresh it
}
```

## Verify with a link

For the link a verification email points to (public, no session needed to call it):

```tsx
function VerifyLinkPage({ token }: { token: string }) {
  const { verifyEmailWithLink } = useAuth();

  useEffect(() => {
    verifyEmailWithLink(token);
  }, [token]);

  return <p>Verifying...</p>;
}
```

`sendVerificationEmail()` is throttled client-side (60s cooldown) - calling it again before that resolves throws, so disable the button while a send is in flight rather than relying only on the throttle to prevent double-clicks.
