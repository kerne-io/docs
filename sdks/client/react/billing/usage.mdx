title: "Usage"
description: "Render a quota meter for the logged-in user"
---

```tsx
import { useUsage } from '@kerne/react';

function ApiCallsMeter() {
  const { usage, isLoading } = useUsage('api_calls');

  if (isLoading) return <Spinner />;
  const record = usage[0];
  if (!record) return null;

  return <p>{record.value} calls used this period</p>;
}
```

Omit `featureKey` to get every QUOTA feature's current usage record in one call:

```tsx
const { usage } = useUsage();
```

Each record: `{ id, feature_key, value, period_start, period_end, status, ... }` - one per feature per open billing period. For the derived `remaining`/`limit` view (accounting for overrides and rollover), prefer [`useAccess`](/sdks/client/react/billing/check-entitlement) or [`useEntitlements`](/sdks/client/react/billing/entitlements-list) - this hook is the raw counter.

## Recording usage

`useReportUsage()` is the write side, always for the signed-in user:

```tsx
import { useReportUsage } from '@kerne/react';

function ExportButton() {
  const { consume, reportBatch } = useReportUsage();

  // gate a QUOTA and commit in one step
  const onExport = () => consume('exports', { delta: 1 });

  // several rows in one request - no manual staggering
  const onSyncAll = (machines) =>
    reportBatch(machines.map((m) => ({ featureKey: 'machine_minutes', delta: m.minutes })));
}
```

- `consume(featureKey, { delta, dimension })` - checks the limit and records, returns the resulting `EntitlementCheck`. Throws a `ValidationError` (with `.fields`) if `delta` isn't a whole number.
- `report(featureKey, { delta, operation, dimension })` - records without a limit check. `dimension` routes the write to the same per-machine/per-project/per-seat counter as `consume()`, but is never required here - omit it and the write lands on the feature's shared counter instead.
- `reportBatch(events)` - up to 100 at once; returns `{ index, status, usage?, error? }[]`, one bad event doesn't sink the rest.
