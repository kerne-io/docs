---
title: "Guard components"
description: "Declarative auth/billing gates - and the error boundary"
---

Each of these wraps a hook you could call yourself - use them when you just need to show/hide UI, reach for the hook directly when you need the loading/error state too.

## Auth guards

```tsx
import { Authenticated, Unauthenticated, AuthLoading } from '@kerne/react';

<AuthLoading><Spinner /></AuthLoading>
<Authenticated fallback={<LoginPrompt />}><Dashboard /></Authenticated>
<Unauthenticated><LoginPrompt /></Unauthenticated>
```

## Billing guards

```tsx
import { HasSubscription, Allows } from '@kerne/react';

<HasSubscription fallback={<UpgradePrompt />}>
  <PremiumArea />
</HasSubscription>

<Allows feature="export_pdf" fallback={<UpgradePrompt />}>
  <ExportButton />
</Allows>
```

There's no plan-slug guard on purpose - matching on a plan **name** breaks silently the moment you rename a plan, or a customer ends up on an equivalent plan under a different slug. `Allows` always checks the actual entitlement instead, so the check keeps working no matter how the plan behind it is restructured.

## Combined guard

```tsx
import { Protected } from '@kerne/react';

<Protected auth feature="export_pdf" authFallback={<Login />} billingFallback={<Upgrade />}>
  <ProFeature />
</Protected>
```

## Error boundary

```tsx
import { KerneErrorBoundary } from '@kerne/react';

<KerneErrorBoundary
  fallback={(error, reset) => (
    <div>
      <p>{error.message}</p>
      <button onClick={reset}>Try again</button>
    </div>
  )}
>
  <App />
</KerneErrorBoundary>
```

`error.code` is available when the thrown error came from an API call (a `KerneError` from `@kerne/server`) - not guaranteed for arbitrary React errors caught by the boundary.
