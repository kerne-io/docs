`@kerne/react` manages the signed-in user's session and adapts your UI to what they can access. It never holds a secret key: every call acts as the signed-in user, on their own data. It works in any React app.

## Install

```bash
npm install @kerne/react
```

```tsx
import { KerneProvider } from '@kerne/react';

export function Root() {
  return (
    <KerneProvider appId={process.env.NEXT_PUBLIC_KERNE_APP_ID!}>
      <App />
    </KerneProvider>
  );
}
```

<ParamField path="appId" type="string" required>
  Your project's app id.
</ParamField>
<ParamField path="autoRefresh" type="boolean" default="true">
  Refresh the session before it expires.
</ParamField>
<ParamField path="refreshBuffer" type="number" default="60">
  How many seconds before expiry to refresh.
</ParamField>
<ParamField path="onAuthChange" type="(user) => void">
  Called when the user signs in or out.
</ParamField>
<ParamField path="onHandoffError" type="(error) => void">
  A sign-in coming from your hosted portal couldn't be completed. See [Session
  handoff](/sdks/client/react/authentication#session-handoff).
</ParamField>
<ParamField path="appearance" type="KerneAppearance">
  Styling for every prebuilt component. See [Styling & language](/sdks/client/react/ui/theming).
</ParamField>
<ParamField path="localization" type="object">
  Text overrides for the prebuilt components.
</ParamField>
<ParamField path="baseUrl" type="string" default="https://api.kerne.io" />

## Guard components

`<Protected>` requires a session, a feature, or both:

```tsx
import { Protected } from '@kerne/react';

<Protected auth featureKey="export_pdf" authFallback={<SignIn />} billingFallback={<Upgrade />}>
  <ExportPanel />
</Protected>;
```

The single-purpose guards are with their hooks: [`<Authenticated>`](/sdks/client/react/authentication#session), [`<Access>`](/sdks/client/react/entitlements#access-guard) and [`<HasSubscription>`](/sdks/client/react/billing#subscription).

## Error boundary

```tsx
import { KerneErrorBoundary } from '@kerne/react';

<KerneErrorBoundary
  fallback={(error, reset) => (
    <p>
      {error.message} <button onClick={reset}>Try again</button>
    </p>
  )}
>
  <App />
</KerneErrorBoundary>;
```

`error.code` is set when the error came from the Kerne API.

## Browser checks are for display

The browser runs on the user's machine, so anything it checks or records can be skipped. Use this SDK to adapt your UI, and check access or record usage from your backend with [`@kerne/server`](/sdks/server/overview) for anything you enforce or bill.
