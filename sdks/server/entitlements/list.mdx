## All entitlements for a subject

Useful for hydrating a settings/billing page without one request per feature:

```typescript
const { entitlements, subscription_status, plan_slug } = await kerne.entitlements({ subject: userId });
// entitlements: [{ feature_key, feature_type, enabled?, limit?, used?, remaining?, overage_behavior?, value?, has_override }, ...]
```

<Note>
There's no `allowed` field here, unlike [`check()`](/sdks/server/entitlements/allows-enforce-check) - this response is cached for 60s, and a stale "allowed" verdict on a QUOTA feature would be unsafe. Use `remaining`/`overage_behavior` to render state (a meter, a badge), and `check()`/`consume()` for the actual go/no-go decision on an action.
</Note>

## Usage records

```typescript
const records = await kerne.usage({ subject: userId });
// or scope to one feature:
const records = await kerne.usage({ subject: userId, featureKey: 'api_calls' });
```

Each record: `{ id, feature_key, value, period_start, period_end, status, ... }` - one per feature per open billing period.
