---
title: "reportUsage()"
description: "Record usage without checking a limit"
---

Unlike [`consume()`](/sdks/server/entitlements/consume), `reportUsage()` never blocks on the limit - it always applies. Use it when the thing you're gating was already allowed some other way (e.g. a background job re-syncing usage counts, or metering something after the fact rather than at the moment of use).

```typescript
await kerne.reportUsage('storage_megabytes', {
  subject: userId,
  delta: 2560,
  operation: 'INCREMENT', // or 'SET' to replace the value outright
  idempotencyKey: syncJobId,
});
```

<ParamField path="subject" type="string" required>
  Required here (unlike `consume()`/`check()`) - there's no self-fallback for this one, you always name a subject.
</ParamField>
<ParamField path="delta" type="number">
  A whole number, defaults to `1`. Meter in the smallest unit you bill (megabytes, not gigabytes) - a fractional delta is rejected, not rounded.
</ParamField>
<ParamField path="operation" type="'INCREMENT' | 'SET'">
  Defaults to `INCREMENT`.
</ParamField>
<ParamField path="idempotencyKey" type="string">
  Same replay-safety as `consume()`.
</ParamField>
<ParamField path="metadata" type="object">
  Arbitrary context stored alongside the usage event (e.g. `request_id`).
</ParamField>
<ParamField path="dimension" type="string">
  Same field as [`consume()`'s `dimension`](/sdks/server/entitlements/consume#dimensions) - routes the write to the right per-dimension counter on a plan that counts per machine, project or seat. One difference: `consume()` requires it on a dimensioned feature (it's gating access), `reportUsage()` doesn't (it never blocks) - omit it there and the write lands on the feature's shared counter instead of a specific dimension.
</ParamField>

## Many at once

`reportUsageBatch()` sends up to 100 events in one request instead of one call each - for a fleet or batch producer reporting several subjects/features at a time.

```typescript
const results = await kerne.reportUsageBatch(
  machines.map((m) => ({
    featureKey: 'machine_minutes',
    subject: m.ownerId,
    dimension: m.id,
    delta: m.minutes,
  })),
);
```

Each event still gets `reportUsage()`'s own transaction and idempotency handling. One bad event (unknown `featureKey`, transient error) fails on its own without discarding the rest - the result is an array of `{ index, status: 'ok' | 'error', usage?, error? }`, so check `status` per entry rather than assuming all-or-nothing.
