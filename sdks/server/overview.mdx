`@kerne/server` runs on your backend. It holds your secret key, so it can check access, record usage and start billing flows for any customer.

## Install

```bash
npm install @kerne/server
```

```typescript
import { Kerne } from '@kerne/server';

export const kerne = new Kerne({
  appId: process.env.KERNE_APP_ID!,
  secretKey: process.env.KERNE_SECRET_KEY!, // sk_live_...
});
```

Both values are in the dashboard under **Settings → API keys**. Keep the secret key on your server: it can act for any customer.

<ParamField path="appId" type="string" required>
  Your project's app id.
</ParamField>
<ParamField path="secretKey" type="string">
  Your secret key. Omit it only to call public routes, such as `billing.plans()` or `auth.config()`.
</ParamField>
<ParamField path="baseUrl" type="string" default="https://api.kerne.io" />
<ParamField path="timeout" type="number" default="30000">
  Request timeout, in milliseconds.
</ParamField>

## Customers

A customer is who a subscription, a usage counter or an override belongs to. Every access and billing call names one with `customer`, the id you bill: a Kerne user id, or any id you choose if you run your own auth.

Anyone who signs up through Kerne already has a customer, with their user id as `externalId`. If you run your own auth, or bill a company rather than a person, register it yourself:

```typescript
const customer = await kerne.customers.upsert({
  externalId: 'org_492',
  email: 'billing@acme.example',
  name: 'Acme Inc.',
  metadata: { crm_id: '0061x' }, // optional
});

await kerne.customers.get('org_492');
await kerne.customers.list({ limit: 50, offset: 0 });
await kerne.customers.update('org_492', { name: 'Acme Corporation' });
```

`upsert()` creates the customer if `externalId` is new, and otherwise fills in the fields it's missing. Renaming `externalId` to one another customer already uses fails with a 409.

Calls that take an `email`, such as `checkout()`, also create the customer on first use, and so does a granted override. `consume()` and `reportUsage()` never do: they reject an unknown id. Register your own customers before you meter them.

`provider_accounts` lists the customer's id at each payment provider (`[{ provider, provider_customer_id }]`). It stays empty until their first checkout.

`kerne.customers` requires your secret key.

## Acting as a user

A secret key isn't tied to anyone, so each call names its `customer`. To make calls as one signed-in user instead, scope a client to their access token. It can then reach only that user's own data:

```typescript
const asUser = kerne.withToken(userAccessToken);
const subscription = await asUser.billing.subscription();
```

## Next.js

Import from `@kerne/server/next`. It's the same client plus a `server-only` guard: the build fails if a Client Component imports it, instead of shipping your secret key to the browser.

```typescript
import { Kerne } from '@kerne/server/next';
```

## Errors

A failed call throws a `KerneError` with `type`, `code`, `message` and `statusCode`, plus `requestId` when the API returned the error.

```typescript
import { EntitlementDeniedError, isKerneError } from '@kerne/server';

try {
  await kerne.enforce('export_pdf', { customer: userId });
} catch (err) {
  if (err instanceof EntitlementDeniedError) return showUpgrade(err.check);
  if (isKerneError(err)) console.error(err.code, err.requestId);
  throw err;
}
```

| Class                    | Thrown when                                                                              |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| `AuthenticationError`    | 401: the key or token is missing or invalid                                              |
| `AuthorizationError`     | 403: the credential can't do this                                                        |
| `EntitlementDeniedError` | [`enforce()`](/sdks/server/entitlements#handle-a-denial) was denied                      |
| `NotFoundError`          | 404                                                                                      |
| `ValidationError`        | 400 or 422: invalid input                                                                |
| `RateLimitError`         | 429; `retryAfter` gives the wait in seconds                                              |
| `NetworkError`           | The API couldn't be reached, or answered with something other than a Kerne JSON response |
| `KerneError`             | Anything else, such as a 500                                                             |

Branch on the class, not on `code`. The API's codes are listed in [Errors](/concepts/error-codes).

## Direct requests

For a route without a typed method, `kerne.request()` sends it with the same base URL and credentials:

```typescript
const records = await kerne.request({
  method: 'GET',
  path: '/v1/billing/usage',
  query: { customer: userId },
});
```
