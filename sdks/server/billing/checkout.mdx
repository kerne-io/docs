---
title: "Checkout"
description: "Create a hosted checkout session"
---

```typescript
const { url } = await kerne.billing.checkout(planPriceId);

// redirect your user to `url`
```

<Warning>
This takes a **`plan_price_id`**, not a plan id - it identifies the specific billing variant (monthly vs. yearly, currency). Sending a plan id here fails with a validation error.
</Warning>

The session is created for the caller's own identity (from their JWT) - this isn't something a secret-key-only backend does on behalf of an arbitrary subject; it's the checkout flow your frontend triggers for the logged-in user (typically proxied through your backend using their own token, see [`withToken()`](/sdks/server/users/me)).

The subscription itself is created asynchronously once the provider (Stripe/Polar) confirms payment - not synchronously when this call returns.

## Where the redirect goes

Checkout success and cancel (and the portal return, see [Portal & cancel](/sdks/server/billing/portal-and-cancel)) all resolve unconditionally to the hosted portal (`apps/portal`):

```
${PORTAL_BASE_URL}/billing?checkout=success&app_id={tenantId}
${PORTAL_BASE_URL}/billing?checkout=cancelled&app_id={tenantId}
```

The portal then hands the session back to your own app: `portal_redirect_url` if you've set one, otherwise `app_url`. Configure either through the tenant configuration endpoint (not yet wrapped by `@kerne/server` - call it directly with your own token, same auth as the rest of this self-service API):

```bash
curl -X PATCH https://api.kerne.io/v1/tenants/YOUR_TENANT_ID/configuration \
  -H "x-app-id: YOUR_APP_ID" \
  -H "Authorization: Bearer $YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "app_url": "https://app.example.com"
  }'
```

`portal_redirect_url` is optional - only set it if the portal should send the user somewhere other than `app_url` once a flow finishes.

<Note>
Auth callbacks (verify email, reset password, magic link) resolve the same way - unconditionally to the portal, which then hands off to `portal_redirect_url` or `app_url`.
</Note>
