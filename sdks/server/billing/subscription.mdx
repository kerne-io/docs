title: "Subscription"
description: "Read the caller's or another subject's subscription"
---

## The caller's own subscription

```typescript
const sub = await kerne.billing.subscription();
// null if they have none
```

## Listing / getting others (admin)

```typescript
const subs = await kerne.billing.subscriptions.list({ status: 'ACTIVE', subjectType: 'USER' });
const one = await kerne.billing.subscriptions.get(subscriptionId);
```

A non-admin caller only ever sees their own subscription(s) regardless of filters passed - `subjectType`/`subject` (the subject filters) only take effect for an admin caller.

## Shape

```json
{
  "id": "sub_...",
  "status": "ACTIVE",
  "plan_price_id": "price_...",
  "current_period_start": "2026-01-01T00:00:00.000Z",
  "current_period_end": "2026-02-01T00:00:00.000Z",
  "plan": { "id": "...", "slug": "pro", "name": "Pro" },
  "plan_price": { "id": "...", "amount": 2900, "currency": "eur", "interval": "1M" },
  "product": { "id": "...", "slug": "acme", "name": "Acme" },
  "entitlements": [
    { "feature_key": "api_calls", "feature_type": "QUOTA", "limit": 10000, "overage": "BLOCK" }
  ]
}
```

`status` is one of `ACTIVE`, `TRIALING`, `PAST_DUE`, `CANCELED`, `UNPAID`, `PAUSED`.

`PAST_DUE` still counts as a live subscription - access isn't cut until, and unless, the product's [billing lifecycle policy](/concepts/monetization/products-and-plans#billing-lifecycle-policy) says so (by default, it never automatically is). `UNPAID` is the status that actually revokes access, reached only through that same policy.
