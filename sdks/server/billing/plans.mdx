---
title: "Plans"
description: "Public pricing data for a pricing page"
---

Read-only, and public - no secret key or user session required beyond `x-app-id`. This is the one catalog read this SDK exposes, specifically for rendering a pricing page.

```typescript
const plans = await kerne.billing.plans(productSlugOrId);
```

Omit the argument to resolve the tenant's default product (`Product.is_default`) - the common case for a tenant with a single product:

```typescript
const plans = await kerne.billing.plans();
```

```json
[
  {
    "id": "plan_...",
    "slug": "pro",
    "name": "Pro",
    "is_default": false,
    "trial_days": 14,
    "prices": [
      {
        "id": "price_...",
        "amount": 2900,
        "currency": "eur",
        "interval": "1M",
        "label": { "slug": "monthly", "name": "Monthly", "sort_order": 0, "display_interval": null }
      }
    ],
    "entitlements": [
      { "feature_key": "api_calls", "feature_type": "QUOTA", "limit": 10000 }
    ]
  }
]
```

`interval` is `{count}{unit}` - `unit` is `D`, `M`, or `Y` (`"1M"` monthly, `"3M"` quarterly, `"1Y"` yearly). Don't parse it yourself for display: `@kerne/react`'s prebuilt components already localize it, and building a pricing page from scratch should split the count and unit rather than showing the raw string to an end user.

`label` groups prices across plans that belong together ("the annual price" for every plan, however each one is priced) - see [Products, plans, and packs](/concepts/monetization/products-and-plans#naming-a-plans-prices).

Features, plans and products are managed in the dashboard under **Catalog**. See [Platform foundations](/concepts/overview) for why that split exists.
