## What is Kerne?

Kerne is the decision layer between your users and your product.

It answers one question on every request:

> What is this user allowed to do, in this product, under this business context?

Instead of scattering authorization logic across identity providers, billing systems, and `if (user.plan === 'pro')` checks, you call a single primitive:

```
User wants to do X  →  kerne.allows('X')  →  Kerne decides
                                              → allowed: your app does X
                                              → denied: your app shows an upgrade prompt
```

That one call — `allows()` — is what replaces scattered plan checks and duplicated business rules across your codebase.

## SDK example

<CodeGroup>
```typescript Server (@kerne/server)
import { Kerne } from '@kerne/server';

const kerne = new Kerne({
  appId: process.env.KERNE_APP_ID!,
  secretKey: process.env.KERNE_SECRET_KEY!, // sk_live_...
});

// Gate an action behind an entitlement, not a plan name
if (await kerne.allows('export_pdf', { scope: userId })) {
  return generatePdf();
}
```

```tsx Client (@kerne/react)
import { KerneProvider, Allows } from '@kerne/react';

function Root() {
  return (
    <KerneProvider appId={process.env.NEXT_PUBLIC_KERNE_APP_ID!}>
      <App />
    </KerneProvider>
  );
}

function ExportButton() {
  return (
    <Allows key="export_pdf" fallback={<UpgradePrompt />}>
      <button onClick={exportPdf}>Export as PDF</button>
    </Allows>
  );
}
```
</CodeGroup>

## What's here today

Kerne currently provides the foundation of that decision layer:

- **Identity** — authentication, sessions, registration modes, waitlist, invitations
- **Billing** — plans, subscriptions, Stripe & Polar
- **Entitlements** — boolean, quota, and static capabilities granted by a plan

Organizations, full RBAC, and policy engines are intentionally not built yet.  
See [Platform foundations](/concepts/overview) for the exact current boundary.
