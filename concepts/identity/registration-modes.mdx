title: 'Registration modes'
description: 'Controlling who can sign up'

Who can create an account is one setting for the whole project: **Settings → Authentication → Who can sign up**. New projects start as **Invite only**.

| Mode            | Who can sign up                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------------- |
| **Open**        | Anyone. Invitations still work.                                                                            |
| **Invite only** | People with a valid invitation: see [Implement invite-only SaaS](/guides/auth/implement-invite-only-saas). |
| **Closed**      | Nobody. You add people yourself, with **Members → Add member**.                                            |

**User limit**, on the same screen, refuses sign-ups once that many accounts exist, whatever the mode.

A refused sign-up fails with `K1001`. Kerne checks on its side, so a request that skips your frontend is refused too.

## Waitlist and invitations

These are two separate things. Joining the waitlist doesn't let anyone in, and doesn't create an account.

- The **waitlist** collects interest: an email and optional details. You later invite the people you pick.
- **Invitations** are what let someone sign up on an invite-only project: a link emailed to one address, or a code you hand out.

## Reading the mode from your app

```typescript
const config = await kerne.auth.config();
// config.registration_mode: 'OPEN' | 'INVITE_ONLY' | 'CLOSED'
```

Build your sign-up form from it, for example an invitation code field on an invite-only project, instead of hardcoding how the project is set up. In React, use `useAuthConfig()`. Every field is in [Auth config](/sdks/server/authentication#auth-config).

## Which one to pick

<CardGroup cols={2}>
  <Card title="Consumer / self-serve" icon="users">
    **Open**. Every extra step loses sign-ups.
  </Card>
  <Card title="Early access / high-touch" icon="building">
    **Invite only**, or a waitlist first. Fewer, better-qualified sign-ups, and room to onboard
    people by hand.
  </Card>
</CardGroup>

You can switch later. Opening sign-up doesn't invalidate codes you already handed out.
