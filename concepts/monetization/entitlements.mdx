title: 'Entitlements'
description: "What a plan actually grants, and how it's checked"
---

Your plans promise things. "Pro includes SSO." "Starter gets 10,000 API calls a month." "Enterprise customers get gold support."

An **entitlement** is one of those promises, made concrete: a named capability with a value, for one specific customer. It's what your application asks about, and it's the reason `allows('sso_enabled')` can keep working after SSO moves from Pro to Enterprise.

Where the value comes from is resolved for you — the plan they're on, the version of that plan they bought, an override negotiated with them specifically. What you configure is the promise; what your code sees is the answer.

Every capability is one of three kinds.

## The three kinds

<Tabs>
  <Tab title="Boolean">
    An on/off switch. `kerne.check()` returns `{ allowed, enabled }`.

    ```typescript
    const { allowed } = await kerne.check('sso_enabled', { subject: userId });
    ```

  </Tab>
  <Tab title="Quota">
    An allowance over a period — `limit`, `used`, `remaining`. You say what it counts (`minute`,
    `token`) and how often it renews (daily, weekly, monthly, or on the billing cycle).

    ```typescript
    const result = await kerne.consume('api_calls', { subject: userId, delta: 1 });
    // { allowed, limit, used, remaining, overage_behavior }
    ```

    `limit: null` means unlimited. What happens once the allowance runs out is a separate choice:
    stop there, let it through untracked, or keep serving and charge for the excess. Counting and
    charging are covered in [Pricing models and meters](/concepts/monetization/usage-billing).

  </Tab>
  <Tab title="Static">
    A config value, not a limit - returned as-is (e.g. `support_level: "gold"`).

    ```typescript
    const { value } = await kerne.check('support_level', { subject: userId });
    ```

  </Tab>
</Tabs>

## Two ways to deviate from the plan for one customer

These solve different problems - don't reach for one when you mean the other:

- **`kerne.admin.grant()`** creates an override: a *replacement limit* that renews every period just like the plan's own limit, until it expires (or forever). This is "this customer has a 1,000/mo deal," not a one-time gift. It covers the whole subject, or [one counter](/sdks/server/admin/overrides) of a feature limited per dimension.
- **`kerne.admin.adjustUsage()`** offsets the usage counter by a signed delta, once. This is "credit this customer 500 units back," and has no effect on their limit going forward.
