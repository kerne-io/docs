This gets one feature gated behind a real subscription, end to end: sign a user up, check what they're entitled to, gate a button on it. Kerne sits in front of the Stripe account you connect - Stripe still moves the money, Kerne decides who's allowed to do what.

## Prerequisites

- Node.js 18 or later
- A Kerne app (`x-app-id`) and, for backend calls, a secret key (`sk_live_...` or `sk_test_...`)

## 1. Install the SDKs

<Tabs>
  <Tab title="npm">
    ```bash
    # For your backend
    npm install @kerne/server

    # For your React frontend
    npm install @kerne/react
    ```
  </Tab>
  <Tab title="pnpm">

    pnpm add @kerne/server @kerne/react

## 2. Backend setup

The server SDK is the only place that should ever hold your secret key - it's what lets you act on behalf of any user (create their subscription, correct their usage, grant an override).

```typescript
// src/lib/kerne.ts
import { Kerne } from '@kerne/server';

export const kerne = new Kerne({
  appId: process.env.KERNE_APP_ID!,
  secretKey: process.env.KERNE_SECRET_KEY!, // sk_live_...
});
```

## 3. Frontend setup

`KerneProvider` never takes a secret key - only `appId`. It manages the session (login state, token refresh) for you.

```tsx
// src/providers.tsx
import { KerneProvider } from '@kerne/react';

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <KerneProvider appId={process.env.NEXT_PUBLIC_KERNE_APP_ID!}>
      {children}
    </KerneProvider>
  );
}
```

## 4. Sign a user up and log them in

<CodeGroup>
```typescript Server
const { token, user } = await kerne.auth.signup({
  email: 'user@example.com',
  password: 'a-strong-password',
});
```

```tsx Client
import { useAuth } from '@kerne/react';

function LoginForm() {
  const { login } = useAuth();

  return (
    <button onClick={() => login({ email, password })}>
      Log in
    </button>
  );
}
```
</CodeGroup>

## 5. Gate a feature behind an entitlement

On the server, `subject` says whose entitlement you're checking - with a secret key there's no "current user", so you always pass it explicitly (it's whatever id you used as `subject_id` when creating the subscription, typically your own user id):

<CodeGroup>
```typescript Server
const canExport = await kerne.allows('export_pdf', { subject: user.id });

if (!canExport) {
  throw new Error('Upgrade required');
}
```

```tsx Client
import { Access } from '@kerne/react';

function ExportButton() {
  return (
    <Access featureKey="export_pdf" fallback={<UpgradePrompt featureKey="export_pdf" />}>
      <button onClick={exportPdf}>Export as PDF</button>
    </Access>
  );
}
```
</CodeGroup>

On the client, `Access` (and the `useAccess` hook) check the *logged-in* user automatically - no subject to pass, the SDK already knows who's authenticated.
