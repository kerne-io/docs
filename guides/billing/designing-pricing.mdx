---
title: "Designing your pricing"
description: "From simple subscriptions to usage-based models"
---

A well-designed pricing model is scalable, easy to understand, and maps directly to your code. Kerne allows you to iterate on pricing without rewriting your application logic.

## The core concepts

1.  **Entitlements (Features)**: What the user *gets* (e.g., "Can export PDF").
2.  **Plans (Tiers)**: A bundle of entitlements (e.g., "Pro Plan").
3.  **Prices (Billing)**: How much they pay for the plan (e.g., "$29/mo").

<Tip>
**Golden Rule**: Your code should check **entitlements**, never plans.
*   **Bad**: `if (user.plan === 'pro')`
*   **Good**: `if (await kerne.allows('export_pdf', { scope: userId }))`
</Tip>

## Model 1: The "Good-Better-Best" (Flat Rate)

This is the standard SaaS model.
- **Free**: Limited features.
- **Pro**: All features.

**Implementation**:
1.  Create features: `can_access_dashboard`, `can_invite_members`.
2.  Create plans:
    - **Free Plan**: Includes `can_access_dashboard`.
    - **Pro Plan**: Includes `can_access_dashboard` + `can_invite_members`.

## Model 2: The "Pay-as-you-go" (Usage Based)

Charge based on consumption (e.g., API calls, emails sent).

**Implementation**:
1.  Create a feature `emails_sent` with type **Quota**.
2.  Set the **Reset Policy**:
    - `RESET`: Counter resets every month (e.g., "1000 emails/mo included").
    - `ACCUMULATE`: Credits roll over (e.g., "Pre-paid email credits").
3.  Report usage via the SDK:
    ```typescript
    await kerne.reportUsage('emails_sent', { scope: userId, delta: 1 });
    ```

## Model 3: Hybrid (base plan + metered add-on)

A flat monthly fee plus a per-unit metered feature - e.g. $20/mo base, then $0.01/email past what's included. Model it as one plan with two entitlements: a boolean/static one for the base tier, and a `QUOTA` one for the metered part, set to `overage: BILL` (see [Entitlements](/concepts/monetization/entitlements) for how `overage_behavior` works).

**Setup, in order:**

1. In Stripe, create a metered price on the product you're billing through Kerne (per-unit or per-tier - Kerne reads whatever pricing shape you set there).
2. In the dashboard, under **Catalog → Plans**, open the entitlement and set **At the limit** to **Bill - charge the excess**, then pick that price under **Metered price**. The rate is read from Stripe, never typed in - if you change the price later, create a new one in Stripe and repoint the entitlement to it.
3. Optionally set a **Billing cap per period** (a money ceiling, e.g. "never bill past €150/month" - past it, usage still counts but stops being forwarded). Leave it empty for a metered add-on meant to scale freely.

From there it's automatic: usage past the included amount gets forwarded to that Stripe price and shows up on the customer's next invoice. Nothing to poll or reconcile yourself - if you want to show the customer what they're about to be charged, read their current usage with [`useUsage`](/sdks/client/react/billing/usage).
