This walkthrough builds one billed feature from scratch. The example is a makerspace that rents laser cutters:

> 0 minutes included · **0.35 € per started hour** · never more than **120 € per customer per billing cycle**.

Swap the numbers for tokens, emails or gigabytes: the steps are the same.

You need Stripe connected (see [Connect your billing provider](/guides/getting-started/subscription-setup)) and a plan other than **Default**: the plan new customers land on can't bill usage.

## 1. Create the feature

In **Catalog**, open your product, click **+ feature** and choose **QUOTA**. Open the new feature and set:

| Field        | Value             |
| ------------ | ----------------- |
| Feature name | Laser cutter time |
| Key          | `cutter_minutes`  |
| Renews       | cycle             |
| Units        | `minute`          |

Count in the smallest unit you bill: minutes, not hours. Counts are whole numbers, so a fraction of an hour has nowhere to go.

Leave the dimension after **Units** empty for one pool per customer. To count each machine separately, name one (`minute` per `cutter`): see [per machine, per project, per seat](/concepts/monetization/usage-billing#per-machine-per-project-per-seat).

## 2. Put it on a plan

Click the feature's cell in your plan's column, then:

1. Set the allowance to `0`.
2. Under **Past the allowance**, choose **Bill it**.
3. Set **Units billed together** to `60`, and **Partial usage** to **rounded up**: a started hour counts whole.
4. Under **Pricing model**, keep **One rate** and enter `0.35`.
5. Open **Advanced config**. Set **Bill at most** to `120`, and **This cap applies** to **globally**: one cap for the whole customer.
6. Under **Billing rate at Stripe**, click **Create it**. Kerne creates the price at Stripe from these numbers.

Then **Save**. If the plan already has subscribers, **Start selling to new subscribers** keeps them on their current terms: see [Change your pricing](/guides/billing/change-your-pricing).

## 3. Count usage from your backend

```typescript
const { allowed } = await kerne.consume('cutter_minutes', {
  customer: customerId,
  delta: 60, // one hour of cutter time
  idempotencyKey: `session-${sessionId}`,
});

if (!allowed) return res.status(403).json({ error: 'usage_not_allowed' });
```

`consume()` checks and counts in one step. With **Bill it** and no unit ceiling, `allowed` stays `true` past the allowance: the excess is billed. Past the 120 € cap, usage still works and is no longer charged: see [why the cap doesn't block](/concepts/monetization/usage-billing#why-the-cap-doesnt-block).

The `idempotencyKey` makes a retry safe: the same key never counts twice. To record usage without checking it, use `reportUsage()`, or `reportUsageBatch()` for up to 100 events: see [Usage](/sdks/server/usage).

Count from your server only. A count sent from a browser can be faked.

## 4. Show it to the customer

```tsx
import { useAccess } from '@kerne/react';

function CutterUsage() {
  const { details } = useAccess('cutter_minutes');
  if (!details) return null;

  return <p>{details.used} minutes this cycle</p>;
}
```

`details` also has `billed_amount` (in cents) and `cap_reached`. It only reads: never count usage from the browser.

## 5. What reaches the invoice

Kerne sends billable usage to Stripe, and it appears on the customer's next invoice as a line priced at your rate. It stops adding up once the 120 € cap is reached.

In the dashboard, **Subscriptions → Usage billing** shows each subscriber's usage, what's billable, and what's been billed so far, with the room left under the cap. At the top, two numbers to watch:

- **Capped**: still using the product, no longer billed for it. Working as designed.
- **Not billing**: Stripe is refusing this usage, for example because the price was archived. Access still works, and revenue is zero.

## Checklist

- [ ] Feature `cutter_minutes`: quota, in minutes, renews every cycle
- [ ] Plan: `0` included, **Bill it**, 0.35 per 60 minutes rounded up, 120 € cap
- [ ] **Create it** clicked, and the edit saved
- [ ] Backend counts with `consume()`, from the server only
