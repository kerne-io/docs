---
title: "Lifecycle: from waitlist to scale"
description: "Which Kerne features fit each stage"
---

<Steps>
  <Step title="Stage 1: Validation">
    Collect interest before writing complex code - close registration and just run a waitlist.

    ```typescript
    await kerne.waitlist.join({ email: 'early-adopter@example.com' });
    ```

    See [Registration modes](/concepts/identity/registration-modes).
  </Step>

  <Step title="Stage 2: Private beta">
    Switch to invite-only, generate codes for specific cohorts (e.g. a launch list), and admit waitlist entries by hand as you're ready for them - see [Implement invite-only SaaS](/guides/auth/implement-invite-only-saas).
  </Step>

  <Step title="Stage 3: Self-serve">
    Open registration, set up plans and checkout (see [Subscription setup](/guides/getting-started/subscription-setup)), and gate premium features by entitlement, not by plan name:

    ```tsx
    import { HasFeature } from '@kerne/react';

    <HasFeature feature="advanced_analytics" fallback={<UpgradePrompt />}>
      <AnalyticsDashboard />
    </HasFeature>
    ```
  </Step>

  <Step title="Stage 4: Negotiated deals">
    For a customer with a custom limit outside your normal plans, use an [entitlement override](/sdks/server/admin/overrides) (`kerne.admin.grant()`) rather than inventing a one-off plan - it's the same mechanism as a normal limit, just scoped to that one customer.

    Not built yet if you need it at this stage: SSO, multi-user organizations, and a first-class "enterprise contract" object - see [Platform foundations](/concepts/overview) for the current boundary.
  </Step>
</Steps>
